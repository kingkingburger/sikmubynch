# SIKMUBYNCH 제작 로드맵

## 로드맵 원칙

이 로드맵은 기능 목록을 많이 채우기 위한 문서가 아니다. 대규모 물량과 방어선의 전투가 재미있다는 것을 먼저 증명하고, 그 위에 필요한 것만 순서대로 얹기 위한 문서다.

우선순위는 다음과 같다.

1. 물량을 감당할 기반 위에서 만든다.
2. 핵심 루프만으로 500마리에서 재미를 증명한다.
3. 첫 화면에서 장르가 보인다.
4. 첫 30초 안에 압박이 느껴진다.
5. 실패 후 다른 배치를 시도하고 싶다.
6. 재미가 증명된 뒤에만 콘텐츠를 얹는다.
7. UI, 사운드, 성능이 상용 빌드 기준에 접근한다.

2026-09-16에 3D를 버리고 2D 쿼터뷰로 가기로 결정했고, 2026-09-21에 증강·보상 카드·시너지·이벤트·유닛·메타를 보류하고 첫 프로토타입을 맵 1/본진 1/방어물 1~2/타워 3/적 3/자원 1/끊기지 않는 압박으로 축소했다(타워는 첫 플레이 후 6종으로). 물량은 100 → 500 → 1,000 → 5,000 → 10,000 순서로 올린다. 기반 전환(단계 B)과 재미 증명(단계 C)이 끝나기 전에는 새 시스템을 추가하지 않는다.

## 단계 A: 문서와 포지셔닝 정리

**목표**: 프로젝트 설명, 게임 디자인, 기술 설계, 검증 기준을 2D 전환과 범위 축소 결정에 맞춘다.

결과물:

- `README.md` 장르 설명 갱신
- `docs/product-brief.md`
- `docs/game-design.md`: 첫 프로토타입 범위와 보류 시스템 구분
- `docs/technical-design.md`
- `docs/production-roadmap.md`
- `docs/quality-plan.md`
- `docs/2d-art-guide.md`
- 오래된 도구 중심 기획 문서 제거

완료 기준:

- 문서에서 특정 내부 도구나 임시 프로세스 이름이 사라진다.
- 외부에 보여줘도 되는 제품 설명이 존재한다.
- 구현 우선순위가 “기능 수”가 아니라 “플레이 약속”으로 정렬된다.
- 문서 어디에도 3D를 전제로 한 설명이 남지 않는다.
- 첫 프로토타입 범위에 없는 시스템이 “보류”로 명확히 구분된다.

## 단계 B: 2D 시뮬레이션 기반과 축소 프로토타입

**목표**: 적·발사체를 Node에서 떼어내 시뮬레이션 배열로 옮기고, 2D 쿼터뷰 렌더러로 그린다. 축소 범위(방어물 1~2, 타워 3, 적 3, 자원 1, 끊기지 않는 압박)로 100마리에서 500마리까지 플레이 가능한 상태를 만든다.

범위:

- Enemy Sim 배열과 MultiMesh 2D 렌더러로 적 이동 구현. 100마리에서 시작해 500마리까지 확인
- Flow Field, Spatial Grid를 2D 격자·인덱스 기반으로 구현
- Combat Sim으로 타워 3종 타겟팅, 발사체, 피해, 감속 구현. 시너지 배율은 없음
- Wave Sim으로 끊기지 않는 압박의 유입률·방향·구성 계산
- 건물(HQ, 방어물 1~2, 타워 3)을 2D Node로 재구성, 쿼터뷰 카메라와 배치·철거
- 최소 HUD: 미네랄, 유입률, HQ 위험, 스폰 방향
- 폴백 스프라이트(색상 마름모)로 전 개체 표시
- 3D 씬, GLB, 3D 제작 도구, 보류 시스템 코드(시너지·카드·이벤트·유닛·배럭·채굴기·버프 타워) 제거
- 렌더러 없는 headless 시뮬레이션 회귀 검증

완료 기준:

- 축소 범위로 런 시작 → 압박 → 본진 파괴 → 재시작이 끝까지 돈다.
- 500마리가 Flow Field를 따라 움직이며 타워에 맞아 죽는 상태에서 시뮬레이션 틱 30Hz, 렌더 60fps를 유지한다.
- 같은 seed에서 렌더러 유무와 관계없이 같은 결과가 나온다.
- 화면이 평면 탑다운이 아니라 쿼터뷰로 보인다.
- 3D 관련 코드·에셋·도구와 보류 시스템 코드가 저장소에서 사라진다.

## 단계 C: 500마리에서 재미 증명

**목표**: 핵심 루프(자원 → 배치 → 끊기지 않는 압박 → 화력 집중 → 유지/붕괴 → 더 큰 압박)만으로 “계속 하고 싶다”는 반응을 만든다. 이 단계를 통과하기 전에는 콘텐츠를 추가하지 않는다.

범위:

- 런 시작 10초 안에 적 무리 시각화
- 첫 방어선이 실제로 밀리는 초반 리듬
- 스폰 방향 경고와 간이 위협 표시
- 압박 변주: 배율·방향 가중치가 예고 없이 떠돎 (웨이브 타입·급증은 2026-09-22에 제거)
- 타워 3종과 적 3종의 역할이 겹치지 않게 수치 조정
- 자원 부족이 배치 판단을 만들도록 비용·보상 조정
- 대량 처치와 방어선 붕괴 피드백 1차: 포격 폭발, 연쇄 처치, 화면 흔들림, 사운드 레이어
- 러셔, 타워, HQ 스프라이트 1차 제작으로 화면 기준 확보

완료 기준:

- 새 플레이어가 첫 런에서 “가만히 있으면 진다”고 이해한다.
- Wave 3 전후에 방어선 일부가 뚫릴 위험이 있다.
- 실패해도 원인이 본진 위험, 방어선 부족, 자원 선택 중 하나로 읽힌다.
- 500마리가 동시에 있는 구간에서 대량 처치가 쾌감으로 느껴진다.
- 플레이테스터가 실패 후 자발적으로 다른 배치로 재시작한다.

## 단계 D: 물량 확장 1,000 → 5,000

**목표**: 재미가 확인된 루프를 유지한 채 물량을 올린다. 병목은 추측하지 않고 측정한다.

범위:

- 1,000마리에서 안정적인 60fps
- 시뮬레이션 틱 시간과 렌더 시간을 분리 측정하는 F3 지표
- 업데이트 빈도 분산, Flow Field 재계산 분산, 이펙트 병합
- 5,000마리에서 플레이 가능한 성능
- GDScript로 목표에 못 미치는 구간만 GDExtension 검토

완료 기준:

- 1,000마리에서 평균 60fps.
- 5,000마리에서 평균 30fps 이상, 시뮬레이션 틱 30Hz 유지.
- 각 단계의 병목 위치와 대응이 측정 기록으로 남는다.
- 물량이 올라가도 화면이 무리로 읽히고 방어선 붕괴 지점이 보인다.

## 단계 E: 콘텐츠 재도입

**목표**: 단계 C를 통과한 뒤, 보류했던 시스템 중 핵심 루프를 실제로 더 재미있게 만드는 것만 하나씩 다시 넣는다.

진입 조건: 단계 C 완료. 이 조건 없이 이 단계를 시작하지 않는다.

재도입 순서 후보:

1. 유닛·배럭: 전선 밖 압박과 누수 처리
2. 레벨업·채굴기: 화력 집중과 확장 판단 강화
3. 시너지·보상 카드: 선택 빈도와 선택지 수를 줄인 형태로 재설계
4. 이벤트·정예·보스: 웨이브 변주

완료 기준:

- 재도입한 시스템마다 “이것이 없을 때보다 계속 하고 싶은가”를 플레이테스트로 확인한다.
- 재도입 후에도 단계 D의 성능 기준을 유지한다.

## 단계 F: 게임 필과 상용 표현

**목표**: 프로토타입처럼 보이는 구간을 줄이고, 반복 플레이를 견디는 피드백을 만든다.

범위:

- 피격/처치/파괴 피드백 정리
- BGM 전환과 핵심 SFX 1차 품질 확보
- UI 색상, 여백, 정보 우선순위 정리
- 전 개체 스프라이트 교체와 실루엣·스케일 통일
- 화면 흔들림과 히트스톱 강도 조정

완료 기준:

- 대량 처치가 시각과 청각 모두에서 쾌감으로 느껴진다.
- 방어선 붕괴와 본진 위험을 UI 없이도 어느 정도 인지할 수 있다.
- 스크린샷 한 장으로 장르가 전달된다.

## 단계 G: 상용 빌드 준비

**목표**: 데모 공개를 검토할 수 있는 안정성을 확보한다.

범위:

- 15~25분 런 안정성
- 설정 저장, 언어 전환, 볼륨 제어
- 크래시/프리즈 재현 루트 정리
- 통계 후보 정의
- 스토어 페이지용 스크린샷/짧은 설명/긴 설명 준비
- 라이선스와 외부 에셋 출처 확인
- 10,000마리 장기 목표 측정

완료 기준:

- 최소 10회 연속 런에서 치명적 크래시가 없다.
- 5,000마리 상황에서 목표 성능을 유지한다.
- 스토어 설명과 실제 게임 화면이 같은 약속을 한다.
- 출시 전 남은 리스크가 문서화되어 있다.
