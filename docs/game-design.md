# SIKMUBYNCH 게임 디자인

## 디자인 목표

SIKMUBYNCH의 목표는 “엄청난 물량이 몰려오고, 플레이어가 전투 중 건설과 배치로 방어선을 유지하는 대규모 디펜스”를 만드는 것이다. 핵심은 복잡한 운영량이나 시스템 수가 아니라, 화면에 보이는 물량 압박과 그 압박을 버티는 배치 판단이다.

플레이어가 화면에서 읽어야 하는 것은 두 가지다. **어디서 얼마나 많은 적이 몰려오는가**, 그리고 **내 방어선이 어디서 무너지고 있는가**. 모든 시스템과 비주얼은 이 두 가지가 즉시 보이도록 설계한다.

시너지 빌드업, 보상 카드, 이벤트 같은 로그라이트 요소는 장기 확장 방향으로 남긴다. 단, 핵심 전투가 재미있다고 증명되기 전에는 넣지 않는다. 2026-09-21에 이 순서를 확정했다.

## 첫 프로토타입 범위

2026-09-21에 확정한 첫 테스트 버전의 범위다. 이 표에 없는 것은 만들지 않는다.

| 항목 | 범위 |
| --- | --- |
| 맵 | 1개 |
| 본진 | 1개 |
| 방어물 | 2종 |
| 타워 | 6종 (2026-09-21 플레이 후 3종에서 확장) |
| 적 | 3종 |
| 자원 | 1종 |
| 압박 | 무한. 끊기지 않는 한 흐름. 웨이브·급증·휴식 없음 |
| 증강 | 없음 |
| 보상 카드 | 없음 |
| 시너지 | 없음 |
| 이벤트 | 없음 |
| 메타 진행 | 없음 |
| 유닛·배럭 | 없음 |

원칙은 **“게임은 작게 만들고, 아키텍처는 크게 만든다”**이다. 첫 프로토타입은 100~500마리에서 재미를 만든다. 구조는 10,000마리까지 확장 가능하게 만든다. 여기서 “이거 계속 하고 싶은데?”라는 반응이 나오면 그때부터 콘텐츠를 추가한다.

## 핵심 루프

```text
자원 획득 (처치 보상 + 소량 기본 수입)
→ 건물 배치 (전투 중에 계속)
→ 적이 끊기지 않고 사방에서 흘러 들어옴 (웨이브·급증 없음)
→ 압박이 예고 없이 두꺼워졌다 옅어졌다 하되 잦아들지 않음
→ 방어선 압박 → 화력 집중
→ 방어선 유지 / 붕괴
→ 시간이 갈수록 유입이 커짐
→ 반복 (쉬는 구간 없음)
```

이 루프만으로 재미있어야 한다. 이것이 재미있으면 나머지는 위에 얹을 수 있다. 반대로 이것이 재미없는데 증강·시너지·이벤트를 추가하면 복잡해질 뿐이다.

## 런 구조

| 항목 | 기준 |
| --- | --- |
| 런 길이 | 일반 목표 15~25분, 빠른 실패 3~8분 |
| 시작 상태 | 본진, 기본 방어물 몇 개, 제한된 미네랄 |
| 첫 압박 | 첫 화면에 이미 적 무리가 보이고, 10초 안에 방어 판단이 필요해야 함 |
| 휴식 | 없음. 웨이브·급증 개념 자체가 없다. 별도 선택 화면도 없음 |
| 실패 | 본진 파괴. 결과 화면에서 버틴 시간, 처치 수, 최대 동시 적 수 표시 |

## 압박 구조: 끊기지 않는 한 흐름

2026-09-21 첫 플레이에서 “웨이브 사이의 휴식이 지루하다”는 판단이 나와 웨이브 라운드를 없애고 스트림 + 주기적 급증으로 바꿨다. 2026-09-22 두 번째 플레이에서 **“중간에 몰아치지 않는다. 웨이브 개념이 없어야 한다”**는 판단이 나왔다. 급증은 카운트다운·배너·6초 덩어리·그 뒤의 잦아듦으로 결국 웨이브였다. 측정으로도 급증 사이마다 동시 적 수가 절반 이하로 떨어졌다(355→141, 327→105). 그래서 **급증을 없애고 그 물량을 스트림에 녹인다.** 압박은 한 층이다.

| 항목 | 규칙 |
| --- | --- |
| 유입 | 런 시작 첫 틱에 수십 마리가 본진 주변에 보이고, 그 뒤로 한 번도 끊기지 않는다. 초당 유입 수는 경과 시간에 따라 계속 오른다(0분 약 4, 5분 약 13, 10분 약 28에 압박 배율을 곱한 값) |
| 압박 배율 | 0.9~1.5 사이를 예고 없이 천천히 떠돈다. 바닥이 0.9라 잦아드는 구간이 없고, 정점은 카운트다운 없이 온다. 첫 2분은 천장이 1.15에서 서서히 열린다 |
| 방향 | **항상 사방에서 온다.** 변마다 가중치가 0.7~1.5를 천천히 떠돌아 한동안 한쪽이 더 두껍다. 위협 레이더는 지금 두꺼운 변을 붉게 표시한다. 변마다 진입로 몇 개가 천천히 옮겨가며 스폰이 그 근처에 모여 기둥처럼 보인다 |
| 거리 | 본진 주변 링에서 시작해 약 3분에 걸쳐 맵 가장자리까지 연속으로 넓어진다. 끊기는 전환 시점이 없다 |
| 구성 | 초반은 러셔만. 45초부터 스플리터, 90초부터 탱크가 섞이기 시작해 각각 18%까지 오른다 |
| 알림 | 급증 배너·경고음·카운트다운은 없다. HUD는 현재 초당 유입 수만 보여 주고, 배율이 높을수록 붉어진다 |

- 적 HP·공격력 배율은 **경과 시간**으로 오른다.
- 결과 화면의 기준은 버틴 시간, 처치 수, 최대 동시 적 수다. “웨이브 N”이나 “급증 N회” 같은 회차 개념은 없다.
- 같은 총량이어도 연속 스트림은 타워가 쉬지 못해 덩어리보다 맵다. 시작 유입 수는 플레이로 다시 정한다.
- 정예와 보스급 압박은 보류 시스템이다.

## 런 상태 규칙

- ESC 메뉴와 수동 일시정지는 각각 정지 사유를 유지한다. 메뉴를 닫아도 남아 있는 수동 일시정지는 해제하지 않는다.
- 수동 일시정지에서는 건설 판단을 할 수 있지만 전투와 스폰은 진행하지 않는다. ESC 메뉴와 게임오버에서는 필드 건설과 철거 입력을 차단한다.
- 새 런은 자원·압박·길찾기·공간 검색·정지 상태를 모두 초기화한다.

### 압박 설계 원칙

- 적은 플레이어가 준비를 마친 뒤 오지 않는다. 준비와 전투가 겹쳐야 한다.
- 초반 압박은 죽일 만큼 강하지 않아도, “가만히 있으면 진다”는 사실을 보여야 한다.
- 중반 압박은 화력을 한곳에 집중하지 않으면 감당하기 어렵게 만든다.
- 후반 압박은 하나의 완벽한 벽이 아니라 여러 겹의 임시 방어선과 광역 화력으로 버티게 한다.
- 물량은 숫자가 아니라 화면이다. 중반에는 수백, 후반에는 수천 단위의 적이 실제로 화면에 보여야 한다. 성능을 이유로 스폰 수를 줄이지 않고 구조로 해결한다.
- 적이 남아 있는데 다음 압박이 겹치는 순간이 장르의 긴장감을 만든다.

## 플레이어 행동

| 행동 | 역할 |
| --- | --- |
| 방어물 배치 | 시간을 벌고 적 밀도를 원하는 위치로 유도 |
| 타워 배치 | 화력의 위치와 종류 결정. 어디에 집중할지가 곧 전략 |
| 철거 | 무너진 방어선을 정리하고 자원 일부를 회수 |
| 카메라·배속 | 압박 지점 확인과 리듬 조절 |

건물 레벨업은 첫 프로토타입에서 뺀다. 화력 집중 판단이 “어디에 짓는가”만으로 이루어지는지 먼저 본다. 필요하면 가장 먼저 재도입한다.

## 건물

타워 6종과 방어물 2종. 2026-09-21 첫 플레이에서 “타워 종류가 너무 적다”는 판단이 나와 3종에서 6종으로 늘렸다. 각 타워는 대량 전투에서 역할이 겹치지 않아야 하고, 발사 방식이 화면에서 바로 구분되어야 한다.

| 건물 | 게임플레이 역할 | 발사 방식 | 유지 기준 |
| --- | --- | --- | --- |
| HQ | 방어 대상, 최후의 보루 | — | 공격받는 순간 위험을 즉시 인지해야 함 |
| 바리케이드 | 싸고 약한 시간벌이 벽 | — | 많이 짓고 많이 부서지는 것이 정상 |
| 강화벽 | 비싸고 튼튼한 벽 | — | 핵심 길목 하나를 오래 버티는 용도 |
| 속사 타워 | 단일 대상 연사, 기본 화력 | 예광탄 발사체 | 가장 싸고 많이 지어 전선을 만드는 기본 선택 |
| 포격 타워 | 광역 폭발, 밀집 처리 | 포물선 셸 + 폭발 | 대량 처치 쾌감의 중심. 느리고 비싸며 밀집 지점에 놓아야 가치가 남 |
| 감속 타워 | 범위 감속 | 냉기 발사체 | 밀도를 한곳에 묶어 다른 타워의 화력 집중 시간을 벌어줌 |
| 화염 타워 | 근거리 지속 광역 | 반경 안 전부 즉시 피해, 화염 파티클 | 방어선 바로 앞 밀집을 갈아내는 근접 광역. 사거리가 짧아 벽 뒤에 둬야 함 |
| 전격 타워 | 연쇄 번개 | 즉발, 인접 적으로 튀는 볼트 | 분열체·소형 무리 처리. 한 발이 여러 마리를 관통하는 것이 보여야 함 |
| 저격 타워 | 장거리 관통 고피해 | 즉발 빔, 직선 관통 | 탱크 처리. 사거리가 가장 길고 느리며, 한 줄로 늘어선 적을 꿰뚫음 |

### 자원 표시 규칙

- 미네랄은 화면에서 가장 먼저 읽히는 숫자다. 크고, 얻을 때 커졌다가 돌아온다.
- 초당 수입과 “+N” 획득 팝업으로 돈이 들어오는 것이 보인다. 팝업은 틱 단위로 합산하고 개별 처치마다 띄우지 않는다.
- 건물 슬롯은 살 수 있으면 밝고 못 사면 어둡다. 비용은 살 수 있으면 초록, 없으면 붉게 표시한다.

### 건물 접촉 규칙

- **적은 길목의 벽만이 아니라 근처의 모든 건물을 공격한다.** 목적지는 본진이지만, 지나는 길에서 2칸 안에 건물이 있으면 방향을 틀어 그 건물을 문다. 타워도 예외가 아니다. 그래서 벽 없이 앞에 세운 타워는 오래 못 버티고, “벽 뒤에 타워”라는 배치가 자연스럽게 생긴다. 공격 슬롯이 꽉 찬 건물은 지나쳐서 다음 건물이나 본진으로 간다.
- 한 건물을 동시에 공격할 수 있는 적 수에는 상한이 있다(타일당 몇 마리). 상한을 넘는 적은 뒤에서 밀집해 기다린다. 그래서 물량은 건물을 순간에 지우는 대신 방어선 앞에 쌓이고, 그 덩어리가 광역 화력의 표적이 된다.
- 본진은 느리게 재생한다. 소수의 새어 들어온 적이 본진을 갉아 런을 끝내지 않고, 실수를 일부 만회할 시간을 준다. 대규모 돌파는 재생으로 버틸 수 없어야 한다.
- 시작 상태는 본진과 4방향 속사 타워 하나씩, 제한된 미네랄이다. 첫 1~2분은 이 방어만으로 버티지만, 유입이 오르면 배치 판단이 필요하다.

## 적

적 3종은 아래를 초안으로 한다. 실루엣과 색만으로 구분되어야 하고, 각각 방어선을 다른 방식으로 시험해야 한다.

| 적 | 역할 | 방어선에 주는 압박 |
| --- | --- | --- |
| 러셔 | 물량의 몸통. 약하고 빠르고 많음 | 화면을 채우고 바리케이드를 갉아먹음 |
| 탱크 | 느리고 튼튼함 | 한 지점을 뚫어 열고, 화력 집중을 강제함 |
| 스플리터 | 죽으면 분열 | 광역 없이 잡으면 물량이 늘어남. 타워 선택을 시험함 |

## 자원

자원은 미네랄 1종이다. 처치 보상과 소량의 기본 수입으로 얻는다. 웨이브 클리어 보상은 웨이브 라운드와 함께 없앴다. 채굴기와 별도 자원 지대는 보류 시스템이다.

- 자원은 항상 부족해야 한다. 모든 곳을 막을 수 없어야 배치 판단이 생긴다. 단, 타워는 싸서 “계속 짓는 손맛”이 있어야 한다. 부족함은 타워 하나의 가격이 아니라 지켜야 할 방향의 수에서 나온다.
- 기본 수입은 방어가 잘 돌아갈 때 손이 멈추지 않게 하는 최소치다. 주 수입은 처치다.
- 철거는 일부만 회수한다. 실수는 비용이 있어야 한다.

## 물량 단계

물량은 처음부터 10,000을 만들지 않는다. 단계마다 “재미가 있는가”와 “병목이 어디인가”를 함께 확인한다.

| 단계 | 목적 |
| --- | --- |
| 100 | 시뮬레이션·렌더러 구조가 돌아가고, 루프가 성립하는지 확인 |
| 500 | 재미를 증명하는 기준 물량. 여기서 “계속 하고 싶다”가 나와야 함 |
| 1,000 | 안정적인 60fps를 유지하며 화면이 무리로 읽히는지 확인 |
| 5,000 | 플레이 가능한 성능. 병목 측정 후 필요한 부분만 최적화 |
| 10,000 | 최종 확장 목표 |

## 맵과 공간

맵은 단순 배경이 아니라 압박의 방향과 두께를 읽고 방어선을 설계하는 판이다. 시점은 2D 쿼터뷰다. 평면 탑다운이 아니라 이소메트릭 시점이며, 3D 모델 디테일 대신 실루엣·색·밀도로 정보를 전달한다.

- 본진은 플레이어가 항상 위치를 이해할 수 있어야 한다.
- 적 타입은 실루엣과 색만으로 구분되어야 한다.
- 밀도는 개체 겹침 자체로 표현한다. 겹침을 피하려고 간격을 벌리면 물량감이 사라진다.
- 스폰 방향은 미니맵 또는 경고 UI로 읽을 수 있어야 한다.
- 첫 프로토타입은 맵 1개다. 너무 넓어져서 압박이 분산되면 안 된다.

## 게임 필

타격감은 개별 공격이 아니라 대량 전투를 기준으로 만든다. 기능을 더 넣는 것이 아니라 방향을 바꾸는 것이다.

```text
적 1마리 맞음 → “퍽”

이것보다

100마리 동시에 공격받음
→ 폭발
→ 연쇄 처치
→ 화면 흔들림
→ 사운드
→ 대량 사망
```

대규모 전투 자체가 보상이어야 한다.

- 피격: 스프라이트 흰색 플래시 + 순간 확대(펀치)로 맞았음을 보여준다. 전체 화면 플래시는 쓰지 않는다.
- 발사: 타워는 쏠 때 총구 섬광이 나고, 탄은 진행 방향으로 늘어난 예광탄으로 보인다. 즉발 무기(전격·저격)는 볼트·빔 선이 한 프레임 이상 남는다.
- 대량 처치: 처치 수에 비례해 이펙트, 사운드 레이어, 화면 흔들림이 함께 커진다. 개별 이펙트 수는 상한을 두고 병합한다.
- 잔해: 죽은 자리에 얼룩이 몇 초 남아 학살의 흔적이 쌓인다. 상한을 두고 오래된 것부터 지운다.
- 방어선 붕괴: 건물 파괴, 경고음, 카메라 반응으로 위험을 즉시 알린다.
- 포격: 폭발 반경 안의 적이 한 번에 사라지는 것이 눈에 보여야 한다.

## 보류 시스템

아래 시스템은 실패한 설계가 아니라, 핵심 전투가 재미있는지 확인하기 전에 너무 일찍 올라간 시스템이다. 500마리 단계에서 “계속 하고 싶다”가 확인된 뒤에만 재도입을 검토한다. 재도입 순서 후보는 유닛·배럭 → 레벨업·채굴기 → 시너지·보상 카드 → 이벤트다. 재도입할 때는 시뮬레이션 구조에 맞춰 다시 설계한다.

### 유닛과 배럭

플레이어가 직접 조작하지 않는 자동전투 유닛. 전선 밖 압박과 누수 처리를 담당한다. 역할 후보: 근접 전선 유지, 원거리 보조 화력, 누수 지점 시간벌이, 밀집 적 처리.

### 시너지 빌드업

건물과 유닛의 특성 태그가 누적되어 단계별 보너스를 여는 시스템. 특성 후보는 화염(광역·지속 피해), 냉기(감속·동결), 독(지속 피해·방어 약화), 전기(연쇄·스턴), 강화(체력·방어). Tier 2 이상은 수치 증가가 아니라 전투 방식이 보이게 달라져야 한다.

### 보상 카드

웨이브 클리어 후 다음 런 방향을 고르는 선택. 해금, 특성 부여, 전역 버프, 위기 대응, 고위험 보상 유형을 가진다. 제작 중 “증강 고르는 게 지겹다”는 판단이 나왔으므로, 재도입한다면 선택 빈도와 선택지 수를 크게 줄이는 것부터 다시 검토한다.

### 이벤트

런마다 같은 빌드가 반복되는 것을 막는 전투·선택 변수. 치명적 이벤트는 최소 3초 전에 경고를 준다.

### 정예·보스

수천 마리 속에서도 즉시 보여야 하는 크고 강한 적. 방어선을 강제로 열게 만드는 장기 생존 테스트 역할이다.

## 비목표

- 정교한 RTS 자원 운영을 핵심으로 만들지 않는다.
- 유닛 직접 명령을 핵심 조작으로 넣지 않는다.
- 긴 캠페인 서사를 우선하지 않는다.
- 핵심 전투가 검증되기 전에 시스템 수를 늘리지 않는다.
- 3D 모델 디테일이나 카메라 회전으로 볼거리를 만들지 않는다. 볼거리는 물량과 방어선 붕괴다.
