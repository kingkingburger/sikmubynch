# SIKMUBYNCH 미완성 작업 목록

확인일: 2026-09-08. 기준 커밋: `4d0b56e`(문서 정리), 게임 코드 기준: `83c1de5`.

## 범위와 판단 기준

현행 제품 설명, 게임 디자인, 기술 설계, 제작 로드맵, 검증 계획, 에셋 가이드, 리팩터링 계획을 현재 소스와 대조했다. 삭제된 과거 기획의 모든 기능을 현재 요구사항으로 되살리지는 않았다.

- **재현**: Godot 4.6.1 headless에서 해당 상태나 계산 결과를 관찰했다. 일부는 내부 함수 호출과 강제 상태 구성을 사용했다.
- **소스 확인**: 호출 경로 또는 구현 누락을 코드로 확인했다. 실제 화면을 조작한 재현은 아니다.
- **부분 구현 / 미구현**: 현행 기획의 목표 중 남은 구현이다. 요구사항과 구현 중 어느 쪽을 바꿀지 결정해야 하는 항목도 포함한다.
- **미검증**: 기능이 없다는 뜻이 아니다. 완료를 판단할 플레이·화면·성능·배포 증거가 부족하다.
- **보류 / 선택**: 문서상 후속 검토 대상이다. 당장 필수인 작업과 구분한다.

P0는 런 진행과 핵심 보상 규칙을 먼저 바로잡을 항목, P1은 플레이 가능한 절편 완성에 필요한 항목, P2는 후속 품질·도구·출시 준비 항목이다. 우선순위는 이번 점검의 제안이다.

총 85개 항목이며, 검증과 보류 과제도 포함한 작업 목록이다. 85개 모두가 버그라는 뜻은 아니다.

## 2026-09-16 방향 변경 반영

3D를 버리고 2D 쿼터뷰로 가며, 적·유닛·발사체를 Node에서 떼어내 시뮬레이션 배열로 옮기기로 결정했다(기술 설계 “기술 결정” 참조). 이 결정으로 아래 항목의 우선순위와 완료 기준이 바뀐다. 표의 원문은 점검 당시 기록으로 유지하고, 여기서 변경 사항만 적는다.

- **F29, F30(모델)**: GLB 부품 보완과 3D 모델 검수는 폐기한다. 2D 아트 가이드의 스프라이트 기준으로 대체하며, 전환 단계 B가 끝난 뒤 스프라이트 검수 항목으로 다시 연다.
- **T01(풀링), T02(업데이트 분산)**: 개별 Node 풀링으로 해결하지 않는다. 시뮬레이션 배열의 free list와 틱 LOD가 이 항목의 새 완료 기준이다.
- **T03(F3 지표)**: 시뮬레이션 틱 시간과 렌더 시간을 분리해 표시하는 것을 완료 기준에 추가한다.
- **T04(회귀 검증)**: 렌더러 없는 headless 시뮬레이션 실행을 검증 기반으로 삼는다. 전환 전 통과하던 검증이 전환 후에도 통과해야 한다.
- **T10(구조 문서)**: 기술 설계와 프로젝트 안내가 목표 구조로 갱신됐다. “현행 구현과 목표 설계를 명시”는 문서에 반영됐고, 구현 완료 시 갱신하는 부분만 남는다.
- **Q11(성능)**: 목표를 500+/2,000+/5,000+ 적, 장기 10,000으로 올린다. 측정 시 틱 시간과 렌더 시간을 분리 기록한다.
- **D02, D03(적·유닛·스포너 리팩터링)**: 기존 파일 분리 방식 대신 Enemy Sim·Combat Sim·Wave Sim 구조로 대체한다. 보류가 아니라 전환 단계 B의 필수 작업이다.
- **D05(MultiMesh)**: 선택 과제가 아니라 전환 단계 B의 필수 작업이다. fog of war, SubViewport 미니맵, 추가 맵 변주는 여전히 선택이다.
- **[model-guide]**, **[model-tool]**, **[ai-model-tool]**: 3D 가이드는 2D 아트 가이드로 대체됐고, 3D 제작 도구는 전환 단계 B에서 제거한다.

## 2026-09-21 범위 축소 반영

증강·보상 카드·시너지·이벤트·유닛·배럭·채굴기·버프 타워·정예·레벨업을 첫 프로토타입에서 보류하고, 범위를 맵 1/본진 1/방어물 1~2/타워 3/적 3/자원 1/무한 웨이브로 축소했다(게임 디자인 “첫 프로토타입 범위” 참조). 물량은 100 → 500 → 1,000 → 5,000 → 10,000 순서로 올린다. 이 결정으로 아래 항목의 처리가 바뀐다. 표의 원문은 점검 당시 기록으로 유지한다.

- **보류 시스템 관련 항목은 해결하지 않고 코드와 함께 제거한다.** 재도입 시 다시 연다.
  - 시너지: F01~F07, Q04, Q13의 시너지 부분
  - 보상 카드: B05, B08, B14, B15, C02, F08~F11, Q05
  - 이벤트: B11, F13의 이벤트 부분, Q06
  - 유닛·배럭: B04, B13, C01, D03의 unit 부분, T03의 유닛 표시
  - 정예: F14의 정예 경고 부분, Q03의 정예 부분
  - 채굴기·자원 지대: F19
  - 레벨업: Q07의 Lv1~3 부분, F23의 레벨 상한 부분
  - 결과 화면·통계의 시너지·빌드 요약: F25, F28의 시너지 부분
- **B01(분열 웨이브 종료)**: 스플리터가 적 3종에 남으므로 유효하다. Enemy Sim 배열 기준으로 Q-SYS-11에서 다시 검증한다.
- **F12(웨이브 타입), F13(압박 겹침), F15(중반 물량)**: 첫 프로토타입 범위에 그대로 남는다. 단, 정예·이벤트 배율 없이 규모·방향·밀도만으로 만든다.
- **F16(시작 배치)**: 기본 방어물 몇 개와 제한된 미네랄로 다시 정의한다. 배럭·채굴기·버프 타워는 시작 선택지에서 빠진다.
- **F21(HQ 위험), F22(선택 패널), F23(피드백 누락)**: 최소 HUD 범위로 유지한다. F22는 타워 3종의 역할·비용 표시로 좁힌다.
- **Q02(초반 균형), Q07(건물 배치)**: “건물 5종”이 아니라 방어물 1~2종과 타워 3종 기준으로 다시 검증한다.
- **Q11(성능)**: 물량 단계별 목표로 바꾼다. 500·1,000에서 평균 60fps, 5,000에서 평균 30fps 이상. 각 단계 병목을 기록한다.
- **D01(배치 리팩터링)**: 특성 등록 부분은 제거된다. 건물 Node 재구성 시 배치·철거 경로를 하나로 만든다.
- **새 항목**: 타워 3종 역할 분리(Q-SYS-10), 대량 처치 집계와 이펙트·사운드 상한(Q-SYS-12), 재미 증명 플레이테스트(Q-PLAY-7)는 검증 계획에 추가됐다. 코드 전환 후 이 목록에 ID를 부여한다.

## 런 안정화 수정 결과

B01~B16, C02의 17개 항목을 수정하고 회귀 검증했다. 초기 점검 85개 중 68개는 후속 구현·검증·보류 항목으로 남는다. 아래 표에서 `완료`로 표시한 행의 문제 설명은 수정 전 재현 기록이며, ID를 유지해 원인과 해결 이력을 추적한다.

- B01~B04: 분열 스폰 큐·카운터, 새 런 FlowField 초기화, 인접 점유 유지, 유닛 공간 검색 갱신.
- B05~B07, C02: 정지 사유 관리, 카드→선택 이벤트 순서, 모달·게임오버 필드 입력 차단.
- B08~B15: 영구 보상 유지, 교차 시너지, 최대 HP, 미네랄 배율, 독 전파, 폭탄병, 카드 설명·효과 일치.
- B16: 게임 씬 진입 시 런 상태를 초기화하여 타이틀 대기 시간을 제외.
- 반복 실행할 수 있는 핵심 회귀 검증을 추가해 T04를 부분 구현 상태로 올렸다. 전체 게임 테스트와 CI는 남는다.

검증 범위·실행 명령·자동 플레이 결과는 [런 안정화 검증 기록](verification/2026-09-08-run-stability.md)을 따른다. B17·B18은 아직 해결하지 않았다.

## 권장 처리 순서

2026-09-21 범위 축소 이후의 순서다. 이전 순서의 2번(카드·시너지 정합)은 보류 시스템 제거로 사라졌다.

1. 전환 단계 B: `sim/`·`render/`를 새로 만들고 축소 범위(방어물 1~2, 타워 3, 적 3, 자원 1, 무한 웨이브)로 런이 끝까지 돌게 한다. 3D 코드와 보류 시스템 코드를 제거한다. B01, D02, D05, T01, T02, T04가 이 단계에서 새 구조로 해결된다.
2. 100 → 500마리 성능과 재현성(Q-SYS-7, Q-SYS-8, Q11)을 기록한다.
3. F12, F13, F15, F16, F17, F21~F23을 축소 범위에 맞춰 다듬고 Q01, Q02, Q-PLAY-7로 첫 5분과 “계속 하고 싶은가”를 검증한다.
4. 1,000 → 5,000 물량 확장과 T03 성능 지표, 장시간·UI 검증을 진행한다.
5. 재미가 증명된 뒤 보류 시스템을 하나씩 재도입한다. 최종 에셋·설정·통계·공개 빌드와 출시 자료는 그 뒤에 정리한다.
