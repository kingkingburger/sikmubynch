# 런 진행·보상 안정화 검증

## 변경 범위

2026-09-08 미완성 목록의 B01~B15와 C02를 순서대로 수정했다. 새 게임 씬의 런 초기화 경계를 고정하면서 B16(타이틀 시간이 런에 포함되는 문제)도 함께 해결했다.

- 분열 자식과 일반 적은 동일한 스폰 큐·카운터를 사용한다. 분열 예약이 남아 있으면 클리어하지 않는다.
- FlowField는 월드 셀 점유와 2×2 셀 점유 수를 구분하고 새 런마다 초기화한다. 유닛은 이동 후 SpatialGrid를 갱신한다.
- 수동 정지·카드·선택 이벤트·ESC·게임오버는 각각 정지 사유를 유지한다. 정지 중 전투·생산·스폰·런 시간이 멈춘다.
- 카드 후 선택 이벤트를 순서대로 표시한다. 모달 뒤의 필드 입력, 음수 인덱스, 이미 처리한 카드 재적용을 차단한다.
- 영구 보상과 일시 이벤트의 저장 영역을 분리했다. 교차 시너지·HQ 최대 HP·처치 미네랄·독 전파·폭탄병 피해를 실제 보상 규칙과 맞췄다.
- 체력 카드는 최대 HP 증가로 적용하고 전설 카드는 추가 회복한다. 특성 카드는 현재 전역 정수 방식에 맞게 설명을 수정했다.

보상 범위·중첩·정지 정책은 [게임 디자인](../game-design.md)에 기록했다. 상위 시너지 신규 효과, 일반 적의 아군 공격 AI, 맵 확장, Steam 기능은 이번 구현 범위에 포함하지 않는다.

## 반복 가능한 검증

Godot 4.6.1을 사용한다. 저장소 루트에서 다음을 실행한다.

```powershell
./tools/run-gameplay-tests.ps1 -GodotPath 'D:/Godot_v4.6.1-stable_win64.exe/Godot_v4.6.1-stable_win64_console.exe'
```

테스트: [gameplay_regression.gd](../../tools/tests/gameplay_regression.gd).

- 1단계: 40개 검증, 실패 0개. 분열 클리어·인접 건물 점유·10회 연속 재시작·아군 이동/사망 등록.
- 2단계: 69개 검증, 실패 0개. 카드 대기 11초·정지 중 스폰/공격·ESC와 정지 사유 유지·이벤트 순서·필드 입력 차단·중복 선택.
- 3단계: 114개 검증, 실패 0개. 영구 보상·Tier/교차 배율·HQ 체력·미래 건물/레벨업·오브 지연 지급·독 Tier별 전파·폭탄병 버프.
- 최종: 타이틀 10초 대기 후 시작 검증을 추가해 115개 검증, 실패 0개.

핵심 결과는 `RESULT: 115 checks, 0 failures`다. 일부 검증은 내부 함수를 호출하고 필요한 상태를 강제로 구성한다. `--fixed-fps 60`은 시뮬레이션 설정이며 실제 렌더링 FPS를 의미하지 않는다. 종료 시 ObjectDB/resource 경고가 남아 있어 B18은 완료 처리하지 않는다. 복합 테스트 종료에서 5개, export된 타이틀 종료에서 1개 리소스가 보고됐다.

## 실제 렌더링을 켠 자동 플레이

[play_smoke.gd](../../tools/tests/play_smoke.gd)는 viewport 마우스 입력으로 타이틀 시작, 건물 슬롯 선택, 타워 배치·레벨업, 보상·이벤트 선택, 게임오버 재시작을 실행한다. 기본 지속 시간은 실제 경과 시간 300초다.

- 초기 자원과 정상 보상만 사용한다. 자원 추가, 무적, 적 강제 처치, 웨이브 강제 완료를 사용하지 않는다.
- 게임 시간이 히트스톱·보상 정지의 영향을 받으므로 실제 경과 시간과 별도로 기록한다.
- 고정 seed와 타워 중심 자동 전략을 사용한다. 사람의 재미·난이도 평가를 대신하지 않는다.
- 시작/전투/보상/게임오버 화면과 매초의 적 수·HP·자원·FPS·런 시간을 `build/play-smoke-<시각>/`에 기록한다.
- 음성 출력은 Dummy 드라이버로 비활성화한다. 사운드 청취 검증은 수행하지 않는다.

```powershell
$repoPath = (Get-Location).Path
& 'D:/Godot_v4.6.1-stable_win64.exe/Godot_v4.6.1-stable_win64_console.exe' --path "$repoPath/project" --audio-driver Dummy --max-fps 60 --script "$repoPath/tools/tests/play_smoke.gd"
```

## 남은 검증 경계

### 5분 실행 결과

- 실제 경과 300.141초, 타워 배치 32회, 보상 선택 5회, 3개 런 관찰, 적 카운터 불일치 0건.
- 첫 런은 W3에서 158킬·게임 시간 85.13초에 패배했고, 두 번째는 W3에서 166킬·105.01초에 패배했다. UI 재시작은 두 번 모두 동작했다.
- 세 번째 런은 제한 시간에 W2·81킬·HQ 약 430.67 HP로 진행 중이었다.
- 최대 동시 적은 64마리였다. 초기 5초를 제외한 매초 FPS 표본 294개의 평균은 59.16, 최저 37, 최고 61이었다. RTX 3060 Laptop GPU, OpenGL Compatibility, 1280×720, 화면 밖 창에서 실행했으며 일부 headless 검증·export를 병행했다. 500+ 적 성능 판정이나 격리된 벤치마크로 사용하지 않는다.
- 실제 캡처로 타이틀·전투·보상 문구·게임오버·종료 시점 화면을 확인했다. 1280×720에서 바뀐 특성 설명은 카드 안에 표시됐다.
- 고정 타워 전략에서 두 번 W3 패배가 관찰됐으므로 다음 밸런스 검증은 Q02의 타워·배럭·혼합 방어 비교를 우선한다. 이 결과만으로 수치를 바로 조정하거나 일반 플레이어의 난이도를 단정하지 않는다.

최초 실행 원본: `build/play-rendered-20260908.log`, `build/play-smoke-20260908/report.json` 및 같은 폴더의 PNG. 이후 실행은 시각별 폴더를 사용한다.

- 출력: `build/SIKMUBYNCH-run-fixes-20260908.exe`. 기존 EXE는 보존했다.
- SHA-256: `5A296A9391330891F696C8126CD2E323EBA6E6813C333DF1478B93B19F401027`.
- 새 EXE를 `--headless --quit-after 120`으로 실행해 타이틀 부팅·종료를 확인했다. 본 게임은 위 소스 프로젝트의 렌더링·UI 자동 플레이로 검증했다.

### 후속 검증

- 500/1000+ 적의 성능 목표, 20~30분 런, 모든 해상도, 일반 플레이어의 실패 납득·재도전 동기는 별도 검증한다.
- Windows release template은 임의 scene path override를 지원하지 않는다. EXE의 타이틀 부팅과 소스 프로젝트의 본 게임 렌더링 검증을 구분한다.
- B17의 BGM 반복 재생, B18의 종료 리소스 경고와 나머지 미완성 항목은 별도 후속 과제로 남긴다.
