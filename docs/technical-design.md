# SIKMUBYNCH 기술 설계

## 목표

기술 설계의 목적은 대규모 호드, 실시간 건설, 시너지 빌드업, 반복 런 구조를 안정적으로 지탱하는 것이다. 구현은 플레이 약속을 기준으로 한다. 성능, UI, 데이터 구조, 시스템 경계는 “500+ 적이 보이는 상황에서 플레이어가 판단할 수 있는가”를 중심으로 결정한다.

## 엔진과 렌더링

- **엔진**: Godot 4
- **언어**: GDScript
- **카메라**: 3D 이소메트릭 정사영
- **렌더러**: GL Compatibility
- **플랫폼**: Windows PC 우선

Godot은 빠른 프로토타이핑, 작은 빌드 크기, 데이터와 씬 편집 편의성이 장점이다. 단, 대규모 적 처리와 UI 정보량은 기본 Node 구성만으로 해결하지 않고 전용 구조로 분리한다.

## 웨이브 압박 구현

웨이브는 `WaveDirector`가 순수 계산에 가깝게 관리한다. 실제 스폰, 큐 처리, 웨이브 완료 판정은 런타임 쪽에서 다룬다.

필요한 데이터:

- 웨이브 번호
- 웨이브 타입
- 총 적 수
- 적 구성 비율
- 스폰 방향과 밀도
- 정예 등장 여부
- 이벤트 배율
- 현재 시너지 대응 난이도

웨이브 수식은 선형 증가만으로 끝내지 않는다. 일정 주기마다 폭풍 웨이브를 배치하고, 정예와 방향 집중을 섞어 방어선의 약점을 시험한다.

## 적 처리와 성능

대규모 적 처리는 다음 원칙을 따른다.

- 근접 탐색은 전역 스캔 대신 `SpatialGrid`를 사용한다.
- 경로는 개별 A* 대신 `FlowField`를 공유한다.
- 발사체와 이펙트는 풀링한다.
- 멀리 있는 적과 가까운 적의 업데이트 빈도를 분리할 수 있게 구조를 둔다.
- F3 디버그 오버레이에는 적 수, FPS, 스폰 큐, 공간 그리드 상태를 노출한다.

목표 성능:

| 상황 | 목표 |
| --- | --- |
| 일반 웨이브 200+ 적 | 평균 60fps |
| 폭풍 웨이브 500+ 적 | 평균 60fps, 순간 45fps 이상 |
| 극한 테스트 1000+ 적 | 평균 30fps 이상 |
| Flow Field 재계산 | 체감 가능한 프리즈 없음 |

## 시너지 시스템

시너지는 중앙 계산을 유지한다. 건물과 유닛은 자신의 특성 태그를 제공하고, `SynergyManager`가 전체 카운트와 단계 보너스를 계산한다.

흐름:

```text
건물/유닛 추가 또는 제거
→ 특성 카운트 재계산
→ 활성 시너지 단계 결정
→ signal synergy_changed
→ UI 갱신
→ 건물/유닛/이펙트 보너스 반영
```

설계 기준:

- 해금만 된 항목은 카운트하지 않는다. 필드에 배치되거나 생산된 대상만 카운트한다.
- 보상 카드가 시너지 단계를 열면 UI에서 미리 보여준다.
- Tier 2 이상은 단순 수치 증가를 넘는 전투 변화가 있어야 한다.

## 보상과 이벤트

보상은 런 방향을 바꾸는 시스템이다. 카드 생성은 현재 웨이브, 활성 특성, 부족한 시너지 카운트, 플레이어의 취약 지점을 고려해야 한다.

보상 생성 입력:

- 현재 웨이브
- 활성 시너지와 다음 단계까지 남은 카운트
- 최근 받은 보상 유형
- 현재 건물/유닛 구성
- 최근 방어선 피해 또는 HQ 피해

이벤트는 별도 확률과 쿨다운을 가진다. 이벤트가 플레이어에게 불공정하게 느껴지지 않도록 위험한 이벤트는 경고 UI와 사운드를 동반한다.

## 데이터 관리

게임 밸런스 데이터는 코드에 흩어지지 않게 정리한다.

- 건물 데이터: 비용, HP, 크기, 기본 DPS, 특성 가능 여부
- 적 데이터: HP, 속도, 공격력, 보상, 특수 행동
- 유닛 데이터: HP, 공격 방식, 생산 주기, 역할
- 시너지 데이터: 단계별 요구 카운트, 보너스, 이펙트
- 웨이브 데이터: 타입, 적 구성, 스폰 방향, 배율

Godot Resource를 기본으로 쓰되, 반복 튜닝이 필요한 값은 한곳에서 찾을 수 있어야 한다.

## UI와 정보 구조

HUD는 많은 정보를 한 번에 보여주되, 우선순위가 있어야 한다.

1. 본진 위험
2. 현재 웨이브와 다음 압박
3. 미네랄과 건설 가능 여부
4. 활성 시너지와 다음 단계
5. 선택 중인 건물/카드의 효과
6. 미니맵의 스폰 방향과 누수 지점

UI는 플레이어가 “왜 죽었는지”와 “다음에 무엇을 바꿔야 하는지”를 이해하게 해야 한다.

## 저장과 통계

런 중 세이브는 핵심 범위가 아니다. 우선순위는 런 종료 통계와 설정 저장이다.

- 최고 웨이브
- 최고 생존 시간
- 총 처치 수
- 자주 사용한 시너지
- 마지막 런 핵심 빌드
- 설정: 언어, 볼륨, 해상도, 전체화면

## 리스크

| 리스크 | 대응 |
| --- | --- |
| 적 규모 증가로 FPS 저하 | SpatialGrid, FlowField, 풀링, 업데이트 분산 |
| 시너지 효과가 수치만 바뀜 | Tier 2 이상은 이펙트와 행동 변화 필수 |
| UI가 복잡해짐 | 위험, 웨이브, 시너지 순으로 정보 우선순위 고정 |
| 웨이브가 반복적으로 느껴짐 | 방향, 밀도, 정예, 이벤트 조합으로 변주 |
| 문서와 구현이 어긋남 | `docs/game-design.md`와 `docs/quality-plan.md` 기준으로 변경 검토 |
