# SIKMUBYNCH 검증 계획

## 검증 목표

검증의 목적은 기능이 존재하는지 확인하는 것이 아니라, 게임의 약속이 실제 플레이에서 느껴지는지 확인하는 것이다.

핵심 질문:

1. 대규모 웨이브 압박이 보이는가?
2. 방어선이 무너질 듯한 긴장감이 있는가?
3. 배치와 화력 집중 판단이 생존 결과를 바꾸는가?
4. 대량 처치가 쾌감으로 느껴지는가?
5. 실패 후 다른 배치로 다시 시작하고 싶은가? 500마리에서 “계속 하고 싶다”가 나오는가?
6. 상용 제품으로 보기에 성능, UI, 사운드, 안정성이 충분한가?

첫 프로토타입 범위(맵 1/본진 1/방어물 1~2/타워 3/적 3/자원 1/무한 웨이브)를 기준으로 검증한다. 보류 시스템(시너지·보상 카드·이벤트·유닛·정예)의 검증 항목은 이 문서에 “보류”로 남겨 두고, 재도입 시 다시 연다.

## 품질 게이트

| 게이트 | 통과 기준 |
| --- | --- |
| 장르 전달 | 첫 30초 안에 적 규모, 본진 위험, 건설 판단이 보임 |
| 물량 가독성 | 2D 쿼터뷰에서 스폰 방향, 밀도, 방어선 붕괴 지점이 UI 없이도 읽힘 |
| 초반 압박 | Wave 1~3에서 방치하면 실제로 위험해짐 |
| 중반 압박 | Wave 8~10에서 500+ 적이 실제로 화면에 보임 |
| 배치 판단 | 같은 웨이브에서 타워 종류와 위치 선택에 따라 생존 결과가 달라짐 |
| 대량 처치 쾌감 | 폭풍 웨이브에서 포격·연쇄 처치가 화면과 소리로 함께 커짐 |
| 실패 납득 | 결과 화면과 플레이 상황으로 주요 실패 원인을 설명할 수 있음 |
| 반복 동기 | 플레이테스터가 다른 배치를 시도하고 싶다고 말함 |
| 재미 증명 | 500마리 단계에서 플레이테스터가 요청 없이 3런 이상 이어서 함 |
| 성능 | 500·1,000에서 평균 60fps, 5,000에서 평균 30fps 이상 |
| 재현성 | 같은 seed에서 렌더러 유무와 관계없이 시뮬레이션 결과가 같음 |
| 안정성 | 20분 런에서 크래시나 진행 불능 없음 |

## 플레이테스트 시나리오

### Q-PLAY-1: 첫 런 이해

- **전제**: 게임을 처음 보는 플레이어
- **행동**: 설명 없이 5분 플레이
- **관찰**:
  - 본진을 지켜야 한다는 목표를 이해했는가?
  - 건설과 전투를 동시에 해야 한다는 사실을 이해했는가?
  - 첫 실패 원인을 말할 수 있는가?
- **통과 기준**: 플레이어가 1분 안에 본진 위험과 건설 필요를 이해한다.

### Q-PLAY-2: 초반 압박

- **전제**: 새 런 시작
- **행동**: Wave 1~3 진행
- **관찰**:
  - 적이 충분히 많아 보이는가?
  - 빠르게 대응하지 않으면 본진이 위험해지는가?
  - 방어물과 타워 선택이 의미 있는가?
- **통과 기준**: 방치하면 실패하고, 적절한 대응을 하면 간신히 넘긴다.

### Q-PLAY-3: 배치와 화력 집중

- **전제**: 타워 3종을 모두 지을 수 있는 자원 상태
- **행동**: 한 방향에 화력을 집중하는 배치와 넓게 펼치는 배치를 각각 시도
- **관찰**:
  - 타워 3종의 역할 차이를 플레이어가 설명할 수 있는가?
  - 포격 타워를 밀집 지점에 놓았을 때와 아닐 때 결과가 다른가?
  - 감속 타워가 다른 타워의 화력 집중 시간을 실제로 벌어주는가?
- **통과 기준**: 플레이어가 “이번 런은 이렇게 배치해서 버텼다”고 설명할 수 있다.

### Q-PLAY-4: 폭풍 웨이브

- **전제**: Wave 8 이상 또는 동등한 중반 테스트 상태
- **행동**: 폭풍 웨이브 관찰
- **관찰**:
  - 방어선이 실제로 밀리는가?
  - 탱크가 무리 속에서 눈에 띄고, 뚫리는 지점이 보이는가?
  - 배치가 생존 결과를 바꾸는가?
  - 대량 처치가 쾌감으로 느껴지는가?
- **통과 기준**: 성공한 배치와 실패한 배치의 차이가 체감되고, 대량 처치 순간이 기억에 남는다.

### Q-PLAY-5: 한 판 더

- **전제**: 같은 배치에서 2회 이상 실패
- **행동**: 결과 화면 확인 후 재시작 여부 관찰
- **관찰**:
  - 실패 이유가 납득되는가?
  - 다음에는 다른 배치를 선택하고 싶은가?
  - 재시작까지의 UI 흐름이 빠른가?
- **통과 기준**: 플레이어가 자발적으로 다른 배치를 시도한다.

### Q-PLAY-6: 물량 가독성

- **전제**: 500+ 적이 스폰되는 폭풍 웨이브 또는 스트레스 상태. 단계 D 이후에는 2,000+로 올린다
- **행동**: 플레이어에게 “지금 가장 위험한 방향은 어디인가”, “탱크는 어디 있는가”를 묻는다
- **관찰**:
  - 방향과 밀도를 5초 안에 답하는가?
  - 탱크를 무리 속에서 가리킬 수 있는가?
  - 방어선이 무너지는 지점을 카메라 이동 없이 찾는가?
- **통과 기준**: 세 질문 모두에 UI 표시 없이도 대체로 맞게 답한다.

### Q-PLAY-7: 재미 증명

- **전제**: 단계 B 완료, 500마리 물량, 축소 범위
- **행동**: 플레이테스터에게 “그만해도 된다”고 말한 뒤 이어서 하는지 관찰
- **관찰**:
  - 요청 없이 몇 런을 이어서 하는가?
  - 그만둔 이유가 “지겹다”인가 “어렵다”인가?
  - 다음에 무엇을 바꿔 보고 싶다고 말하는가?
- **통과 기준**: 3런 이상 이어서 하고, 그만둔 이유가 “지겹다”가 아니다. 이 시나리오를 통과하기 전에는 콘텐츠를 추가하지 않는다.

| Q-SYS-2 | 보상 카드 | 보류 | 재도입 시 다시 정의 |

| Q-SYS-5 | 경로 탐색 | 다양한 방어물 배치 | 적이 멈추거나 비정상 관통하지 않음 |
| Q-SYS-6 | 재시작 | 10회 연속 런 시작/사망 | 자원, 건물, 적, 웨이브 상태가 초기화 |
| Q-SYS-7 | 시뮬레이션 재현성 | 같은 seed로 렌더러 있음/없음 각 3회 실행 | 웨이브별 생존 적 수, HQ HP, 킬 카운트가 동일 |

| Q-SYS-9 | 정지·배속 | 일시정지, 2배속 상태에서 틱 카운트 기록 | 정지 중 틱이 0회, 배속 중 틱이 배수로 호출 |
| Q-SYS-10 | 타워 3종 역할 | 같은 웨이브에 타워 1종씩만 배치 | 속사·포격·감속의 처치 수와 방어선 유지 시간이 뚜렷하게 다름 |
| Q-SYS-11 | 분열 처리 | 스플리터만 스폰 | 분열 자식이 배열에 정상 추가되고, 모두 제거된 뒤 웨이브가 한 번만 종료 |
| Q-SYS-12 | 대량 처치 집계 | 포격으로 50+ 동시 처치 | 처치가 한 틱 이벤트로 묶이고 이펙트·사운드가 상한 안에서 재생 |

## 성능 검증

| 단계 | 목표 | 측정 |
| --- | --- | --- |
| 100 적 | 구조 동작, 재현성 | headless 틱 시간, 렌더러 있음/없음 결과 비교 |
| 500 적 | 평균 60fps | F3 오버레이 또는 로그, 30초 구간 |
| 1,000 적 | 평균 60fps | 30초 구간, 틱 시간과 렌더 시간 분리 |
| 5,000 적 | 평균 30fps 이상, 틱 30Hz | 별도 스트레스 상태, 병목 위치 기록 |
| 10,000 적 | 틱 30Hz 유지 | 장기 목표. 틱 시간 로깅, 렌더 시간과 분리 기록 |
| Flow Field 재계산 | 체감 프리즈 없음 | 재계산 시간 로깅 |
| 장시간 런 | 메모리 증가율 안정 | 20분 이상 플레이 |

측정 시 하드웨어, 해상도, 배속, 빌드 종류를 함께 기록한다. 시뮬레이션 틱 시간과 렌더 프레임 시간은 항상 따로 적어 병목 위치를 판단한다. 각 단계의 병목과 대응은 기록으로 남기고, 다음 단계로 넘어가기 전에 이전 단계 목표를 다시 확인한다.

## UI 검증

- 현재 웨이브와 다음 위험을 1초 안에 읽을 수 있는가?
- 본진 위험이 HUD와 화면 연출 모두에서 드러나는가?
- 미네랄 부족, 배치 불가 여부가 즉시 보이는가?
- 선택 중인 건물의 역할과 비용이 명확한가?
- 수백 마리 적 속에서 탱크와 붕괴 지점이 구분되는가?
- 1080p, 1440p, 4K에서 텍스트와 버튼이 겹치지 않는가?

## 비주얼 검증

| 항목 | 기준 |
| --- | --- |
| 시점 | 스크린샷이 평면 탑다운이 아니라 쿼터뷰로 읽힘 |
| 실루엣 | 줌 1.0에서 적 3종, 타워 3종이 실루엣만으로 구분됨 |
| 밀도 | 500마리 겹침 상태에서 개체가 뭉개지지 않고 무리로 보임 |
| 깊이 | 건물·적의 앞뒤 관계가 어긋나는 장면이 없음 |
| 폭발 | 포격 반경 안의 적이 같은 프레임에 사라지는 것이 보임 |
| 플레이스홀더 | 색상 마름모 폴백이 남은 개체가 없음 (단계 F 이후) |

검수는 아트 가이드의 3장면(초반 20마리, 중반 500마리, 폭풍 2,000마리) 스크린샷으로 한다.

## 사운드와 타격감 검증

| 항목 | 기준 |
| --- | --- |
| 일반 피격 | 반복되어도 피로하지 않은 짧은 피드백 |
| 대량 처치 | 처치 수에 비례해 화면과 사운드가 함께 커지는 보상감. 개별 재생이 겹쳐 소음이 되지 않음 |
| 포격 폭발 | 반경 처치가 하나의 큰 타격으로 들림 |
| 탱크 돌파 | 방어선이 뚫리는 순간을 놓치지 않게 하는 경고 |
| 건물 파괴 | 방어선 붕괴를 놓치지 않게 하는 사운드 |
| 웨이브 시작 | 다음 압박이 온다는 긴장감 |

## 완료 정의

작업 완료는 파일이 바뀐 상태가 아니라 검증 증거가 있는 상태다.

- 게임플레이 변경: 해당 시나리오 직접 플레이 또는 자동 검증 결과 필요
- 밸런스 변경: 전후 수치와 플레이 영향 기록 필요
- UI 변경: 주요 해상도 스크린샷 또는 직접 확인 필요
- 성능 변경: 시뮬레이션 틱 시간과 FPS 로그 필요
- 2D 전환 단계: headless 회귀 검증이 통과하고, 500 적 성능 결과가 기록되어야 함
- 물량 단계 상승: 이전 단계 목표 재확인과 새 단계 병목 기록 필요
- 콘텐츠 재도입: Q-PLAY-7 통과 기록이 먼저 있어야 함
- 문서 변경: 오래된 용어와 새 기준의 충돌 여부 확인 필요
