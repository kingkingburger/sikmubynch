# SIKMUBYNCH 검증 계획

## 검증 목표

검증의 목적은 기능이 존재하는지 확인하는 것이 아니라, 게임의 약속이 실제 플레이에서 느껴지는지 확인하는 것이다.

핵심 질문:

1. 대규모 웨이브 압박이 보이는가?
2. 방어선이 무너질 듯한 긴장감이 있는가?
3. 시너지 선택이 전투 양상을 바꾸는가?
4. 실패 후 다른 빌드로 다시 시작하고 싶은가?
5. 상용 제품으로 보기에 성능, UI, 사운드, 안정성이 충분한가?

## 품질 게이트

| 게이트 | 통과 기준 |
| --- | --- |
| 장르 전달 | 첫 30초 안에 적 규모, 본진 위험, 건설 판단이 보임 |
| 초반 압박 | Wave 1~3에서 방치하면 실제로 위험해짐 |
| 중반 압박 | Wave 8~10에서 200+ 적 또는 동등한 시각 압박이 보임 |
| 시너지 체감 | Tier 2 이상이 수치뿐 아니라 공격 방식, 범위, 상태 이상, 생존력 변화로 보임 |
| 실패 납득 | 결과 화면과 플레이 상황으로 주요 실패 원인을 설명할 수 있음 |
| 반복 동기 | 플레이테스터가 다른 보상/시너지 경로를 시도하고 싶다고 말함 |
| 성능 | 500+ 적 상황에서 평균 60fps 목표, 순간 45fps 이상 |
| 안정성 | 20분 런에서 크래시나 진행 불능 없음 |

## 플레이테스트 시나리오

### Q-PLAY-1: 첫 런 이해

- **전제**: 게임을 처음 보는 플레이어
- **행동**: 설명 없이 5분 플레이
- **관찰**:
  - 본진을 지켜야 한다는 목표를 이해했는가?
  - 건설과 전투를 동시에 해야 한다는 사실을 이해했는가?
  - 첫 실패 원인을 말할 수 있는가?
- **통과 기준**: 플레이어가 1분 안에 본진 위험과 건설 필요를 이해한다.

### Q-PLAY-2: 초반 압박

- **전제**: 새 런 시작
- **행동**: Wave 1~3 진행
- **관찰**:
  - 적이 충분히 많아 보이는가?
  - 빠르게 대응하지 않으면 본진이 위험해지는가?
  - 바리케이드와 타워 선택이 의미 있는가?
- **통과 기준**: 방치하면 실패하고, 적절한 대응을 하면 간신히 넘긴다.

### Q-PLAY-3: 시너지 빌드업

- **전제**: 보상 카드 3회 이상 선택
- **행동**: 하나의 특성 또는 크로스 시너지를 의식적으로 추적
- **관찰**:
  - 다음 단계까지 필요한 카운트가 보이는가?
  - 보상 카드가 시너지 달성 여부를 알려주는가?
  - Tier 상승 후 전투 변화가 보이는가?
- **통과 기준**: 플레이어가 “이번 런은 화염/냉기/전기 빌드였다”고 설명할 수 있다.

### Q-PLAY-4: 폭풍 웨이브

- **전제**: Wave 8 이상 또는 동등한 중반 테스트 상태
- **행동**: 폭풍 웨이브와 정예 등장 관찰
- **관찰**:
  - 방어선이 실제로 밀리는가?
  - 정예 또는 특수 적이 눈에 띄는가?
  - 시너지와 배치가 생존 결과를 바꾸는가?
- **통과 기준**: 성공한 빌드와 실패한 빌드의 차이가 체감된다.

### Q-PLAY-5: 한 판 더

- **전제**: 같은 빌드에서 2회 이상 실패
- **행동**: 결과 화면 확인 후 재시작 여부 관찰
- **관찰**:
  - 실패 이유가 납득되는가?
  - 다음에는 다른 보상 또는 배치를 선택하고 싶은가?
  - 재시작까지의 UI 흐름이 빠른가?
- **통과 기준**: 플레이어가 자발적으로 다른 빌드를 시도한다.

## 시스템 검증

| ID | 항목 | 검증 방법 | 통과 기준 |
| --- | --- | --- | --- |
| Q-SYS-1 | 웨이브 진행 | Wave 1~10 수동 플레이 | 적 수, 스폰 방향, 타입 변화가 의도대로 진행 |
| Q-SYS-2 | 보상 카드 | 20회 카드 선택 로그 | 해금, 특성, 버프, 위기 대응 카드가 편향 없이 등장 |
| Q-SYS-3 | 시너지 발동 | 각 특성 Tier 1~3 강제 구성 | UI, 보너스, 이펙트, 사운드가 동기화 |
| Q-SYS-4 | 이벤트 | 전투/선택 이벤트 강제 발동 | 경고, 효과, 종료 처리가 정상 |
| Q-SYS-5 | 경로 탐색 | 다양한 바리케이드 배치 | 적이 멈추거나 비정상 관통하지 않음 |
| Q-SYS-6 | 재시작 | 10회 연속 런 시작/사망 | 자원, 건물, 적, 시너지 상태가 초기화 |

## UI 검증

- 현재 웨이브와 다음 위험을 1초 안에 읽을 수 있는가?
- 본진 위험이 HUD와 화면 연출 모두에서 드러나는가?
- 미네랄 부족, 배치 불가, 레벨업 가능 여부가 즉시 보이는가?
- 활성 시너지와 다음 단계까지 남은 카운트가 명확한가?
- 보상 카드에서 즉시 효과와 장기 빌드 가치가 구분되는가?
- 1080p, 1440p, 4K에서 텍스트와 버튼이 겹치지 않는가?

## 사운드와 타격감 검증

| 항목 | 기준 |
| --- | --- |
| 일반 피격 | 반복되어도 피로하지 않은 짧은 피드백 |
| 대량 처치 | 화면과 사운드가 함께 커지는 보상감 |
| 정예 등장 | 플레이어가 즉시 위험을 인지하는 경고 |
| 건물 파괴 | 방어선 붕괴를 놓치지 않게 하는 사운드 |
| 시너지 발동 | 빌드 단계 상승을 축하하는 명확한 피드백 |
| 보상 선택 | 전투 중 긴장과 선택의 휴식감을 분리 |

## 출시 준비 검증

출시 준비 단계에서는 아래 항목을 별도 체크한다.

- Windows 빌드 실행과 종료가 안정적인가?
- 설정 저장과 재실행 복원이 동작하는가?
- 언어 전환이 주요 UI에 반영되는가?
- 스토어 설명, 스크린샷, 실제 게임 화면의 약속이 일치하는가?
- 외부 에셋, 사운드, 모델의 상용 사용 권리가 확인되었는가?
- 크래시 재현 로그와 최소 진단 정보가 남는가?
- 데모 빌드와 개발 빌드의 차이가 문서화되어 있는가?

## 완료 정의

작업 완료는 파일이 바뀐 상태가 아니라 검증 증거가 있는 상태다.

- 게임플레이 변경: 해당 시나리오 직접 플레이 또는 자동 검증 결과 필요
- 밸런스 변경: 전후 수치와 플레이 영향 기록 필요
- UI 변경: 주요 해상도 스크린샷 또는 직접 확인 필요
- 성능 변경: FPS 또는 처리 시간 로그 필요
- 문서 변경: 오래된 용어와 새 기준의 충돌 여부 확인 필요
